# AI辅助 —— 本文档由 AI 协助编写与校对

> voidImageViewer PLUS 1.1.17-rc.1 修复轮总结
> 适用读者：普通使用者。愿意细看技术细节的人请看文末"七、反馈渠道"里指出的仓库审计文档。

## 一、这个版本是什么

1.1.17-rc.1 是一个**预发布（RC）**版本：功能已经完整，但建议先试用一段时间、发现的问题会在下一个版本里继续修，之后才发正式版。

这一轮的目标是清理上一版本反馈的问题。在发布过程中，我们又发现并当场修复了一个新暴露的缺陷：Windows 有一个"查询文件属性"的接口只返回属性、不返回文件名，程序此前误把一段没有写入过的内存当作文件名去比较，于是"打开文件"这一类入口全部被误拦——表现为点了文件却没有任何反应。现已修复（详见六的表格第一行）。

## 二、修好了什么（用户视角）

- **打开文件恢复可靠**：命令行、双击文件关联、最近文件、file->open 这些入口重新可用，不会再"静默没反应"。
- **打不开就明说**：文件太长、超出图像预算、或者文件损坏时，状态栏会给出一条明确的提示，而不是显示一片空白。
- **拖放/文件夹不再无声丢文件**：播放列表跳过的文件会汇总成一条提示（告诉你是哪些、为什么），而不是悄悄消失。
- **幻灯片不再快进失控**：把播放速度设成非法值（比如 0）时，会回退到默认速度。
- **配置坏了有选择**：设置文件损坏时，程序会先保住原文件，再给出明确的处理选择，而不是悄悄丢配置或悄悄写坏。
- **安装包更安全**：三个平台的安装器与 zip 都启用了 ASLR/DEP/CFG（三种内存防护）编译选项。

## 三、怎么验证的

- **自动测试**：5 套"钉子测试"（字节不变量、缩放数学、菜单结构、行为模拟、像素基准）全部通过。
- **真机烟囱测试**：在发布流程里用真实程序跑了 55 个样本，包括故意损坏的图片、超预算的图片和一个 4GB+ 的假大文件——全部按预期拒绝或正常显示，无一崩溃。
- **发布产物**：x64 / x86 / arm64 三个平台各有 zip 和安装器，附带 sha256 校验清单。

## 四、已知限制（诚实列出）

- **Win7 真机未测试**：这轮只在 Windows 10+ 的开发机上通过了构建与验证。代码层面没有引入任何 Win 用不了的接口，但欢迎 Win7 用户实测反馈。
- **部分文案暂无中文**：本轮新增的一些界面文字暂时只有英文，下个版本补齐。
- **一个已知小缺陷**：菜单 File → Add file… 目前会把文件加进播放列表，但列表里的路径指向错误，切换到那一项会提示找不到文件——改用拖放或直接打开不受影响。下个 RC 修复。
- **还有几个轻量级小项**在排队（滚轮余量、动画计时清理等），属于下一轮清单。

## 五、怎么获取与试用

1. 打开 GitHub 仓库的 **Releases** 页面，选择 **1.1.17-rc.2**（页面上标着 Pre-release）。
2. 按设备选择下载：
   - **x64**——大多数 64 位 Windows；
   - **x86**——32 位 Windows；
   - **arm64**——高通/ARM 架构的 Windows 设备。
   每个平台既有免安装的 zip，也有安装器 Setup。
3. 如需校验完整性，将下载文件的 sha256 与清单 `sha256.txt` 对照。
4. 试用建议：多试几类图片（png/jpg/gif/webp）、拖放一个文件夹、玩一下播放列表与幻灯片、切换界面语言和深色模式。
5. 遇到问题请到 GitHub 的 issue 区反馈：附上 Windows 版本、安装方式（Setup 还是 zip）、以及"做了什么、期望什么、实际发生什么"。

## 八、rc.2 追记（2026-10-18，随 1.1.17-rc.2 入库）

本文写成于 rc.1 发布后的现场。对第四节已知限制逐条交底：Add file 路径已修；弹窗文案进表，但设置页 Reset 确认框与播放列表跳过状态栏行仍是英文（下一轮补齐）；轻量级小项（滚轮余量、动画计时清理等）本轮未触碰；Win7 真机测试仍开放。另有两条 rc.1 发布后的用户实测反馈同轮修复：

- **File → Add file 路径指向错误**：rc.1 把"文件全路径"传进了"目录"参数位，播放项被排到 `...\a.png\a.png`。rc.2 改传父目录（保留尾分隔符），行指向你选中的文件。
- **部分文案暂无中文**：损坏设置弹窗的标题、按钮与正文全部进入本地化表（简体中文与英文）。
- **升级弹窗误判（rc.1 发布后用户实测反馈）**：读取器的畸形行检查错放在字符循环内部——任何含键行的设置文件都被判"读不干净"、每次退出都弹窗。rc.2 把检查放回循环外；历代写出的设置重新判干净，真正损坏的行仍会报告。
- **卸载残留（同为实测反馈）**：`.corrupt.` 副本与 `.auditbak` 现在随"删除设置"的答案一并清扫，`%APPDATA%\voidImageViewer` 不再被拽住。

技术叙事见 `Changes.txt` 与 `audit/fix-2026-10-17-resume.md` 的 rc.2 追记；用户向说明见 `README.md` / `README_CN.md`。
