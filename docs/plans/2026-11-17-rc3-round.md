> **For implementer:** TDD throughout. The repo's test culture is Python pin/simulation
> tests (`tests/menu_structure_test.py` pins exact source lines; `tests/simulation_test.py`

**Goal:** ship the user's rc.3 round — responsive 4K/DPI toolbar, toolbar/status-bar
rework, non-destructive temp rotation, fullscreen buttons, queue fixes, OpenGL removal,

**Architecture:** one repo (`/home/z/my-project/work/repo`, main at 682395e = rc.2).
Renderers share one contract (`_viv_hw*_render(hwnd,hdc,hbitmap,dst…,clear)`, 0 = GDI
fallback). Overflow ladder lives in `viv_toolbar.c`'s measure/walk. Status bar is a
subclass-drawn fact strip in `viv_chrome.c`.

**Verified by web research (user asked):** PerMonitorV2 reflow is the Microsoft fix for
high-DPI chrome; OpenGL on Windows falls back to GDI-generic GL 1.1 (the wrap-probe
problem this tree already fought) — D3D is the right Windows back end; JPEG 90° is only
lossless via MCU-aligned transform, so a temp-copy + shell rotate verb keeps the original
untouched; D3D12 staging/upload buffers must be freed after the GPU consumes them.

### Task F2: D3D11 + D3D12 renderers + render self-check

**New files** `src/hwd3d11.{c,h}`, `src/hwd3d12.{c,h}` — same contract as `hwd3d.h`
(render/shutdown/release_image/available/export_begin/export_filled). Dynamic module
loads only (os.c precedent; PE import table unchanged): d3d11.dll / d3d12.dll / dxgi.dll
/ d3dcompiler_47.dll. Zig's mingw tree carries d3d11.h, d3d12.h, d3dcompiler.h (verified).
HLSL compiled at runtime via `D3DCompile` (no fxc needed).

**Memory rules (user: 注意内存):** one device/context/swapchain per window; exactly one
image texture alive (freed by `release_image` on every switch); D3D11 uploads straight
from the DIB section bits via `UpdateSubresource` (no staging pool); D3D12 keeps one
upload buffer (regrown only when a bigger image arrives) and frees nothing per frame;
fence waits only on init/resize.

**Render self-check (渲染图自检验):** each backend, on the first successful present of a
newly uploaded texture, draws the image 1:1 into an offscreen target, reads back a
5-point sample grid (4 corners inset + center), compares against the DIB section's own
pixels (free — frames are CreateDIBSection bitmaps), and logs via `debug_printf`. A
mismatch sets the existing `_viv_hw_render_fallback` flag — the session falls back to GDI
and the status line says why. Runs once per image, not per frame.

**Selection:** `config_renderer` gains `CONFIG_RENDERER_DIRECT3D11 3` /
`CONFIG_RENDERER_DIRECT3D12 4`; view menu radio gains both rows (availability-gated);
the settings hardware-acceleration switch and the installer box pick the best available
(12→11→9) and the desc names the choice; legacy `renderer=1` (removed OpenGL) maps to 2.

**Dispatch:** `src/viv_wndproc.c` paint path walks GDI→D3D9→D3D11→D3D12;
`src/viv_export.c` gains the export hooks for the golden line.

Verify: zig build; `tools/pe_header_check.py`; new `tests/d3d_renderers_test.py` pins
contract + dispatch + legacy map + self-check wiring and simulates the NDC/sample math;
gl_runtime step gone from CI.
